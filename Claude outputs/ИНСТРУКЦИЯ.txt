ОБНОВЛЕНИЕ n8n ДЛЯ ГРАФИКА (отпуск, обмен сменами, обед)

ЧТО В ПАПКЕ
1. «Сайт График Компании (обновлённый).json» — workflow с вебхуком /pyrus/graph.
2. «Пайрус-Манго Автоматика (обновлённый).json» — workflow с группами Манго.

ШАГ 1. Создать таблицу данных pyrus-lunch (Data tables, тот же проект, что и остальные)
Все колонки строковые, кроме member_id (число):
seg_id, member_id, name, phone_number, start_utc, end_utc, status, ended_at

ШАГ 2. Импорт
Импортируйте оба файла как новые workflow (Import from file), проверьте работу, затем отключите старые и включите новые.
В нодах «Обеды: все», «Обед: запись», «Обеды: сейчас», «Обеды: открытые», «Обед: обновить статус» выберите таблицу pyrus-lunch из списка (если n8n не подставил её сам). В нодах pyrus-raspisanie таблица уже выбрана.
Важно: у нового workflow «Пайрус-Манго» адрес вебхука mango/sync. Если хост у вас не quumahienot.beget.app, поправьте URL в ноде «Манго: пересобрать группы» основного workflow.

ШАГ 3. Секреты
В обоих файлах ключ бота Pyrus и ключи Манго записаны прямо в нодах (как и в ваших исходных файлах). Рекомендую перенести их в Credentials и перевыпустить ключи, так как файлы уже пересылались.

КАК ЭТО РАБОТАЕТ

Основной workflow, новая ветка Switch «actions» (шесть типов: vacation_create, vacation_delete, schedule_swap, lunch_status, lunch_start, lunch_end):
запрос → токен Pyrus → чтение таблицы обедов и таблицы смен → Code «Действия: логика» → ответ сайту. Параллельно: запись изменений обеда в таблицу и, если нужно, вызов вебхука Манго для пересборки групп.

Права: роли берутся из Pyrus (/v4/roles) по user_id из запроса. Роль 1271289 редактирует все линии; 1271290 — ПНР (OV); 1271291 — ОП (OP). Значения в начале Code-ноды, их можно править.

Отпуск: создаёт задачу формы 2383799 (период = start_utc + duration_minutes, сотрудник), удаление — DELETE задачи с проверкой формы и прав.

Обмен сменами: у двух задач формы смен меняется только поле «Сотрудник». Перед этим проверяется, что у получателя нет другой смены в тот же день, обмен только внутри одной линии; если вторая половина обмена не прошла, первая откатывается. Сотрудник может менять только свои смены, редактор линии — любые. Передача смены (без второй задачи) работает так же.

Обед: сотрудник должен быть на смене прямо сейчас (ищется в pyrus-raspisanie по ФИО). Лимит — 1 час в сутки, можно использовать несколькими заходами; заход можно запланировать на время позже внутри смены. Состояние хранится в таблице pyrus-lunch (одна строка на заход, статусы scheduled → active → returned или cancelled).

Workflow Манго:
— ветка заполнения групп теперь читает активные обеды и не включает обедающих сотрудников в группы (сравнение по phone_number);
— у неё два новых входа: вебхук mango/sync (сайт дёргает его сразу после старта/конца обеда и обмена на сегодня) и «Таймер обедов» раз в минуту: запланированный обед становится активным, просроченный закрывается; если что-то изменилось, группы пересобираются;
— пятиминутный запуск работает как раньше, но уже с учётом обедов.

ИСПРАВЛЕНИЯ В СУЩЕСТВУЮЩЕМ ВЕТКЕ pyrus_save
— создание смены без шаблона (кастомная): убрано пустое "item_id": (JSON был невалидным), поле «Шаблон» не отправляется;
— изменение смены на кастомную: поле «Шаблон» очищается (item_id: null), раньше ветка дублировала обычную;
— ответ сохранения теперь содержит { tasks, deletedIds }, сайт показывает результат сразу, не дожидаясь реестра Pyrus.

ПРОВЕРКА ПОСЛЕ ИМПОРТА
1. Запросом POST на /pyrus/graph с {"type":"lunch_status","user_id":<id>} должно прийти {onShift, lunch, canStart ...}.
2. На сайте: поставить кастомную смену, отпуск, обменять две смены, нажать «Обед» (в рабочее время при наличии смены в таблице).
3. В Манго проверить, что после старта обеда оператор пропал из группы в течение минуты, а после возврата вернулся.

ОГРАНИЧЕНИЯ
— Таблица pyrus-raspisanie заполняется вашей текущей автоматикой; обед не сработает, если смена туда ещё не попала или в строке нет phone_number.
— Токен Pyrus для новых действий берётся отдельной нодой «Pyrus: токен» (копия вашей).


ВХОД ПО ПИСЬМУ С КНОПКОЙ И ДУБЛЬ В PYRUS (ветка email)
Письмо: заменён шаблон в ноде «Send email» — крупная кнопка «Войти в график» и код ниже для ручного ввода; светлая и тёмная тема, мобильная вёрстка. Ссылка кнопки: адрес сайта + ?li_email=...&li_code=...
Дубль в Pyrus: параллельно письму нода «Pyrus: дублировать вход» создаёт задачу на форме «Уведомления» (form_id 2472720): Тип = «Авторизация в графике», Почта, Пин-код, Сотрудник. Номер формы взят из адреса вашего скриншота (pyrus.com/t#et2472720); если у формы другой id, поправьте FORM_ID в начале кода ноды. Поля: Тип = 2, Почта = 3, Пин-код = 4, Сотрудник = 6.
Кнопка «Войти» в самой форме Pyrus: в настройках поля «Войти» укажите ссылку
https://mixailsh01-blip.github.io/chart-PosService/?li_email=${Почта}&li_code=${Пин-код}
(Pyrus сам подставит и закодирует значения полей).
Сайт: при загрузке читает li_email / li_code, сверяет с кодом, который сам же запросил (хранится 10 минут в браузере), и входит без ввода. Если ссылку открыли в другом браузере или на другом устройстве, показывается обычный экран входа с подсказкой ввести код вручную.
